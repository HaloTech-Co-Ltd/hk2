# REPL 与 TUI

[English](../../en/guides/repl-and-tui.md) | 简体中文

本指南介绍 hk2 的两个交互前端——默认的行式 REPL 与 `--tui` 内联 TUI——
以及前端选择、按键、补全、历史、状态栏、工具卡片、思考输出与任务中输入
框。两个前端运行同一套会话、斜杠命令与智能体回合处理流程；差别只在渲染。

## 选择前端

- **行式 REPL（默认）**——`hk2`。经典 readline 提示符
  （`hk2(项目|Eden/N Holy/N|模型)>`）、状态栏与工具卡片。在 TUI 不可用时
  作为回退，包括管道 / 非 TTY 输入路径。
- **内联 TUI**——`hk2 --tui`（或 `HK2_UI=tui`）。Claude Code 风格的界面：
  底部固定带边框的多行输入框、终端原生回滚区里的流式 markdown 回答与
  工具卡片、实时状态行、斜杠命令补全、方向键确认弹窗。

解析顺序（优先级从高到低）：`--tui` 选项、`--repl` 选项、`HK2_UI` 环境
变量（默认 `repl`）。

**TTY 能力检测**：TUI 需要 raw 模式 stdin、TTY 输出，并且 `TERM` 未设置或不等于
`dumb`。任何不满足——非 TTY 的输入 / 输出、`TERM=dumb`、某些 CI 控制台——
都会带提示自动回落到 REPL。TUI 默认绘制到 stderr；`HK2_TUI_STREAM=stdout` 可
切换（能力检测跟随实际使用的流）。

## REPL 行编辑与补全

- **实时补全菜单**——输入 `/` 加前缀即弹出补全菜单（无需 Tab）：↑↓ 选择，
  pageup/pagedown 翻 5 项，Tab/Enter 采纳，唯一精确匹配时 Enter 直接提交，
  esc 关闭直到输入再次变化。菜单与命令共用同一数据源派生，随命令变化保持一致。
- **数据参数补全**——模型引用、会话 id 与项目 id 根据注册表实时提供补全：
  `/model use|set|del|set-default|set-phase|add-mcpserver <ref>`、
  `/session resume|info <id>`、`/resume <id>`、
  `/project set current|drop <id>`。`/model set-phase --phase=` 补全阶段
  枚举。`HK2_REPL_HINTS=0` 恢复无提示的朴素提示符。
- **Tab** 采纳高亮的补全项；常规 readline 编辑（历史、光标移动）照常。
- **输入法与粘贴编辑**——单行括号粘贴和输入法一次提交的多字符会插入到当前
  光标位置；即使刚在行中删除字符或移动光标，也不会被追加到行尾或发生字符错序。
- **多行输入**——多行粘贴会先保存为一份待提交草稿；在空提示符处按 Enter，
  才会把整块内容作为一条消息提交。若改为输入替换文本，则会丢弃这份待提交
  草稿。也可用 `\` 结尾手动续行。

## TUI 按键

| 按键 | 作用 |
|---|---|
| enter | 发送消息（空输入不发送） |
| `\` + enter | 续行而不是发送（斜杠命令行尾的反斜杠照常提交） |
| alt+enter / ctrl+j | 插入真实换行 |
| ↑ / ↓ | 单行时切换历史；多行时跨折行移动 |
| ← / →、home / end、ctrl+a / ctrl+e | 光标移动 |
| ctrl+k / ctrl+u / ctrl+w / alt+退格 | 删到行尾 / 行首 / 光标前一个词 |
| Tab | 采纳高亮的斜杠补全项 |
| ctrl+r | 历史增量搜索：输入子串过滤，↑↓（或连按 ctrl+r）循环匹配，enter 把选中项填回输入框，esc 关闭 |
| esc / ctrl+g | 回合运行中：中断回合。否则：关闭补全菜单 / 取消当前弹窗 |
| ctrl+l | 清屏（对话记录保留在终端回滚里） |
| ctrl+o | 展开最近一次工具结果到对话区（紧凑行只显示一行 + "+N lines"） |
| ctrl+c | 清空输入；输入为空且回合运行中则中断；输入为空且空闲时连续按两次退出（按其它键立即解除"再按一次退出"状态） |
| ctrl+d | 空缓冲时退出（否则向前删除） |

## 自适应布局与欢迎卡

界面自适应终端宽度：≥ 88 列显示带提示面板的完整欢迎卡，60–87 列显示紧凑单栏
卡片，更窄时只显示两行摘要，避免内容超出终端宽度。已有会话的用户（以及高度
不足 30 行的终端）始终使用紧凑形态；`/clear` 只打印一行会话摘要，不再重画
整张卡。

`HK2_WELCOME` 指定档位：`auto`（默认——首启完整，老用户 / 矮屏紧凑）、
`full`（宽度允许时强制显示 logo 卡）、`compact`（跳过 logo 卡；极窄终端
仍用两行摘要）。

菜单与弹窗的选中项永远用 `❯` 标记，绝不只靠颜色区分。弹窗问题文本自动
换行并显示对应的按键提示行：确认弹窗使用
`↑↓ select · enter confirm · esc cancel · y/n[/e]`，选项列表另有 `1-9 jump`，
自由文本输入使用 `enter submit · esc cancel`。

## 状态栏

终端底部固定显示一条状态栏（仅 TTY 模式）：

```text
streaming │ myapp | Eden/9 Holy/1 | local/mymodel │ ↑1.4k ↓120 0.1%/128k │ 4.2s · esc to interrupt
```

- `↑1.4k`——当前智能体循环（正在处理的这条用户输入）中**单次 LLM 调用的
  最大输入** token 数；`↓120`——单次调用的最大输出。均为峰值，既不是全部
  LLM 调用的总和，也不是最近一次调用的数字。
- `0.1%`——输入峰值除以配置的上下文窗口
- `128k`——上下文窗口大小

在流式输出、工具调用与阶段切换期间实时更新。有活跃计划时，进度面板显示
在状态栏上方（见[规划与审查](planning-and-review.md)）。

## 工具卡片与思考输出

每次工具调用渲染为一张紧凑卡片（边框颜色可通过 `/theme` 自定义）；
`ctrl+o` 展开最近一张。思考输出（推理模型的 `reasoning_content`）默认折叠
——TUI 显示 `Thought for Ns`，REPL 的 `✎ thinking` 窗口最多渲染 9 行内容
并报告隐藏了多少行。设置 `HK2_HIDE_THINKING=0` 可在两个前端实时流式显示
完整推理。

## 零配置首启

未配置默认模型且不存在 `claude` 提供商时，`hk2 --tui` 会自动从 Claude Code 的
`~/.claude/settings.json` 导入一个模型（取 `env` 块的
`ANTHROPIC_BASE_URL` + `ANTHROPIC_AUTH_TOKEN` / `ANTHROPIC_API_KEY`，
模型提示来自 `ANTHROPIC_DEFAULT_*_MODEL` 与 `ANTHROPIC_MODEL`，并会去重；若均未设置，
导入器会填充 `claude-sonnet-4-6`）。欢迎卡下方会显示导入提示。仅填充——已有默认模型或 `claude` 提供商时绝不覆盖；
设 `HK2_AUTOIMPORT_CLAUDE=0` 可禁用。见
[模型、项目与会话](models-projects-and-sessions.md)。

开始对话仍需先初始化项目：hk2 以知识库为基础，在 `/project init` +
`/kb init` 完成之前消息会被拒绝并给出初始化指引——即使首启导入已经配置
好了模型。

## 任务运行中继续输入

任务运行期间，底部会在计划面板 / 状态栏上方固定显示一行输入框
（`» add instruction ▏`），**终端中的实际光标会停在输入框内**——闪烁光标恰好
正好位于你输入文本将出现的位置（并跟随光标在文本中间的移动）。你的输入实时
回显在这里——这个专用输入框布局可将草稿与常规流式重绘隔离。

- 任务中输入的**纯文本**进入队列（回显
  `✓ queued #N · delivered after the current action`），在智能体循环的
  轮次边界注入当前对话——即当前动作（本轮 LLM 调用及其全部工具
  调用）执行完毕之后、下一次 LLM 调用开始之前。模型会将其视为任务内指引
  （"融入正在进行的工作，不要从头开始"），当前动作不会被打断。
- **斜杠命令**保持旧行为——会在回合结束后执行，因为它可能变更正在运行的
  回合所依赖的模型 / 知识库 / 项目状态。计划确认菜单不受影响。
- 共享的斜杠命令形状守卫只会将首 token 符合
  `^/[A-Za-z][A-Za-z0-9_-]*$` 的输入视为命令形状。已注册的 `/kb` 等命令正常
  分发，形状合理但拼写错误的 `/mdoel` 可得到 did-you-mean 建议。`/tmp/example.md`
  等绝对路径、`/foo已更新` 等与路径粘连的正文、隐藏 / 波浪线形式、裸 `/` 与全角
  `／model` 都继续作为普通智能体输入。同一规则用于分发、任务中输入捕获和多行粘贴
  收集器：真正的斜杠命令会等待当前任务结束，而路径样式文本会排队或留在粘贴批次中。
- 如果任务在队列指令送达前结束，该指令会在紧随其后的新回合处理
  ——在正常运行和正常回合结束的路径中，你输入的内容不会丢失（进程崩溃或被
  强杀不在保证范围内）。

## 输入历史及其权限

输入历史持久化在 `~/.hk2/history.jsonl`（上限 1000 条）。该历史与配置存储
有两个安全属性：

- 匹配当前凭据识别模式（`--api-key=…`、`--token=…`、`Authorization` 头、
  `password=`/`secret=` 赋值）的输入会被排除出输入历史；识别基于模式匹配，
  并不能识别任意形式的秘密表示。
- `~/.hk2/history.jsonl` 与 `models.json` 保持仅属主可读（0600，启动时自动
  迁移，`~/.hk2` 目录本身 0700）。
