# 安全与权限

[English](../../en/guides/security-and-permissions.md) | 简体中文

本文档说明 hk2 的文件系统权限模型：智能体可以读、写、执行什么；规则存放
在哪里；如何解析；以及——明确地——该模型*不*保护什么。内容依据
`lib/config/setting.js` 与 `setting.example.json` 核验。

## r / w / x 权限模型

hk2 对所有内置本地路径工具（`read` / `write` / `edit` / `find` /
`grep` / `ast_grep` / `ast_edit` / `resolve`，以及对 `bash` 命令的尽力
扫描）实施类 Unix 的权限模型：

- `r`——读文件 / 列目录
- `w`——创建 / 修改 / 删除
- `x`——执行（bash 命令引用该路径）

- **项目内：默认宽松。** 当前项目根（`cwd` + `HK2_PROJECT_SOURCE`）内的
  路径默认完全可操作——文件与目录一律 `rwx`——但显式规则与硬拒绝的配置
  路径会覆盖它（项目路径上的 `allow: r` 规则会把它变为只读；见下文）。
- **项目外：默认拒绝。** 不在项目根内的路径，除非规则授权，否则一律拒绝。
- 目录上的规则覆盖**其下所有内容**（同目录权限位语义）；文件上的规则只
  覆盖该文件。规则始终递归——尾部 `/**` 可写可不写，等价于目录本身。

## 配置文件

两层配置合并生效（仓库根目录有 `setting.example.json` 可参考）。两层均
位于 `HK2_HOME` 下（默认 `~/.hk2`，通常在项目树之外）——但 `HK2_HOME` 可以
指向任意位置，因此真正的保证是另一回事：**无论文件在哪里，对
`setting.json` 与 `settings/**` 的智能体写入都被硬拒绝**，模型无法改写
约束自己沙箱的规则：

> **重装警告**：当安装目录同时也是 `~/.hk2`（默认）时，从外部检出重新运行
> `install.sh` 会**删除 `setting.json` 与 `settings/`**——它们不在安装器的
> 保留清单里（只保留 models/projects/theme/kb/sessions/logs）。请先备份，
> 或用独立的 `HK2_INSTALL_DIR` 安装；见[安装](../getting-started/installation.md)。

- `~/.hk2/setting.json`——全局基线
- `~/.hk2/settings/<project-id>/setting.json`——项目级覆盖

project-id 取自 `HK2_PROJECT_ID`（交互模式下自动设置）或按 source 路径从
`projects.json` 反查；未注册的项目没有项目层。

```json
{
  "permissions": [
    { "path": "/tmp/scratch",      "allow": "rw"  },
    { "path": "~/Documents/notes", "allow": "r"   },
    { "path": "secrets",           "deny":  "rwx" },
    { "path": "node_modules",      "deny":  "w"   }
  ]
}
```

相对路径相对项目根解析；`~` 展开为用户主目录。

> **迁移说明**：该布局出现前，项目级文件位于 `<项目根>/setting.json`。
> 该位置现在**被忽略**——智能体对项目根有写权限，项目根内的规则文件可能
> 被自行授予。请把规则移到 `~/.hk2/settings/<project-id>/setting.json`
> （或合并进全局文件）。加载时打印的告警会同时给出两个路径。

## 规则解析

**最长匹配前缀优先**；同前缀时项目层压过全局层，同层内 `deny` 压过
`allow`。

`allow: "r"` 意味着**只读**——不会回退到项目内的宽松默认。显式规则完全
决定目标的权限位。

非法配置（如 `"allow": "q"`、缺少 `allow`/`deny` 字段、或同条规则同时写了
两者）在加载时以警告形式上报并指明被丢弃的条目——仅丢弃受影响的规则，
其余有效规则继续生效。丢弃不改变基础策略：项目根之外一切照旧默认拒绝，
项目之内宽松默认仍然生效。空数组 `permissions: []` 是合法的"无规则"配置，
不会告警。

## 哪里强制执行

### 强化路径：文件工具

`read` / `write` / `edit` / `find` / `grep` / `ast_grep` / `ast_edit` /
`resolve` 在触碰路径前直接检查权限。

- **递归工具**（`find` / `grep` / `ast_grep` / `ast_edit` 目录展开）对每个
  下降进入的目录和每个输出的文件重验 `r`——即使遍历从祖先目录（如项目
  根）发起，子目录上的 `deny` 规则同样生效。
- `ast_edit` 暂存的写入在 `resolve` 时逐文件复验。

### 尽力而为路径：`bash`

`bash` 约束扫描命令字符串中显式出现的绝对路径 / `../` 形式路径、含斜杠
的相对操作数（按命令的有效基目录解析——通过 `cd` 序列跟踪），以及被执行
目标（如 `bash script.sh` / `node x.js` 这类解释器调用操作数，或直接调用
的绝对路径可执行文件）。被执行目标要求 `x`；数据操作数按只读命令验 `r`、
变更类命令（`rm` / `mv` / 重定向等）验 `w`。

> **shell 是图灵完备的。** 该扫描是防误伤护栏，不是硬沙箱——命令可以构造
> 出扫描器看不见的路径。专用文件工具才是强化路径；请把 `bash` 的权限检查
> 视为尽力而为。

### 权限配置对智能体只读

即使某条 `allow` 规则覆盖了 `HK2_HOME`，对 `~/.hk2/setting.json` 与
`~/.hk2/settings/` 下任意内容的写操作也会被硬拒绝——只有用户本人才能编辑
沙箱定义。

## 符号链接

词法上位于项目内、但经符号链接实际指向项目外位置的路径会被拒绝——真实
路径按同一套规则复验。反过来，按任一拼写（词法或真实）写的 `allow` 规则
都能同时匹配两种形式，因此允许规则在符号链接系统上依然有效。

## 知识库继承源文件权限

对源文件的 `read` 拒绝会抑制**显式镜像文件内容**的知识库通道：

- **受过滤通道**（源文件被拒绝时抑制）：`kb_search` 的摘要与源码切片
  （切片还会跳过超过 512 KiB 的文件）、`kb_symbol` / `kb_outline` /
  `kb_class` 的 docString，以及每轮自动注入的知识库上下文（符号摘要、
  收集的文档正文、结构化文档表格）。
- **拒绝后仍可能可见**——不会按原文件读取权限重新过滤的索引派生材料：
  符号名、限定名、种类、**签名**（源码派生：参数名、类型、默认值）、行号
  范围、图谱关系（导入 / 继承 / 包含），以及已保存的 Holy/Eden 知识条目
  正文——包括 `intro` 源自原始文档文本的 `doc:<relpath>` Eden 条目、
  `kb_search_knowledge` 的 intro 预览，以及 `kb_knowledge` 返回的完整条目
  （它可能直接读取磁盘知识存储）。

> **保密性警告**：当前的 `r` 拒绝**不是**对规则生效前已写入知识库数据的
> 完整保密边界。它会抑制上面列出的显式过滤镜像通道，但源码派生的签名、
> 图谱元数据与已保存的 Holy/Eden 条目正文仍可能可见。若保密要求包含已
> 索引数据，需要删除或重建相关知识库数据。

## 凭据与文件权限

- 命中当前凭据识别模式（`--api-key=…`、`--token=…`、`Authorization` 头、
  `password=`/`secret=` 赋值）的输入不会写入输入历史。识别基于模式匹配
  ——覆盖这些常见形态，不保证任何形式的秘密都一定被检出。
- `~/.hk2` 以 0700 创建；`models.json`、`projects.json` 与
  `~/.hk2/history.jsonl` 保持仅属主可读（0600，启动时自动迁移）。
- MCP 服务器 options 只保存 `$APIKEY` 占位符——提供商密钥在使用时替换，
  绝不持久化在 options 中。

## 限制与威胁模型

该模型旨在提供：

- 结构化文件工具在项目之外的硬边界；
- 权限配置本身免受智能体写入；
- 源文件读取权限贯穿到知识库派生内容。

它**不**提供：

- 完整的操作系统级沙箱。`bash` 检查是词法层面的尽力扫描；坚决的或混淆
  过的 shell 代码可以绕过它。请像对待任何编码智能体一样谨慎使用 hk2：
  最小权限规则、可达路径不放置机密、不可信代码先审查再执行。
- 网络隔离。没有任何机制限制智能体的 `bash` 命令或 MCP 服务器可以访问的
  网络。
- MCP 服务器**内部**的任何约束。本地权限服务检查的是内置工具
  （`read`/`write`/`edit`/`find`/`grep`/`ast_*` 等）；外部 MCP 服务器自身的
  文件或网络访问不受这些路径检查约束——请独立地信任与限制 MCP 服务器。
